# Шлюз к открытым моделям

API DeepSeek, Kimi и GLM в формате OpenAI с рублёвым балансом. Покупатель берёт код пополнения на Plati или GGSel, активирует его на сайте и получает ключ `sk-…`. Запросы уходят к ProxyAPI, с баланса списывается стоимость по фактическому расходу токенов.

Шлюз пропускает только модели из `models.js`. Туда входят модели разработчиков, которые сами разрешают работу с Россией и встраивание API в свои сервисы. GPT, Claude, Gemini и другие закрытые для России модели отклоняются с ошибкой 404 ещё до обращения к поставщику.

## Из чего состоит

| Часть | Где работает | Что делает |
|---|---|---|
| Сайт (`public/index.html`, оферта, политика) | GitHub Pages | Активация кодов, баланс, цены, примеры подключения |
| Шлюз (`server.js`, база SQLite) | Сервер с HTTPS, например Amvera | `/v1/chat/completions`, `/v1/models`, `/api/redeem`, `/api/me`, `/admin/*` |

GitHub Pages умеет отдавать только статические файлы, поэтому API и база живут на отдельном сервере. Страница на Pages обращается к нему напрямую.

## Локально

```bash
npm run dev    # шлюз с имитацией поставщика на http://localhost:8790, в консоли — три демо-кода по 100 ₽
npm test       # 16 проверок: списания, фильтр моделей, потоковый режим, ошибки поставщика, админка
```

Внешних зависимостей нет. Нужен Node.js 22.13 или новее: в нём есть встроенный SQLite.

## Перед запуском

1. Получите ключ в личном кабинете ProxyAPI, положите его в `.env` (образец в `.env.example`) и выполните:
   ```bash
   npm run upstream-models
   ```
   Команда покажет, какие идентификаторы из `models.js` у ProxyAPI действительно есть. Идентификаторы в `models.js` указаны по их схеме `разработчик/модель`, но не сверены. Поправьте их и цены по [тарифам ProxyAPI](https://proxyapi.ru/pricing).
2. Спросите поддержку ProxyAPI, через кого они обслуживают `deepseek/*`, `moonshotai/*` и `z-ai/*`: напрямую через API разработчиков или через американских посредников. Если через посредников, эти модели продавать нельзя. Чтобы их убрать, удалите строку в `models.js`.
3. Заполните реквизиты для оферты и политики: `SELLER_NAME`, `SELLER_INN`, `CONTACT_EMAIL`, `HOSTING_NAME`. Покажите тексты юристу: это черновик.

## Сервер на Amvera

Amvera — российский хостинг. Он выдаёт бесплатный адрес с HTTPS вида `https://<проект>-<логин>.amvera.io` и хранит базу в `/data` между перезапусками. `amvera.yml` и `Dockerfile` уже в репозитории.

1. Создайте проект в Amvera и отправьте в него репозиторий через git.
2. В разделе «Переменные» задайте:
   - секреты: `UPSTREAM_KEY` и `ADMIN_TOKEN` (случайная строка не короче 32 символов);
   - обычные переменные: `MARKUP`, `BRAND`, `SELLER_NAME`, `SELLER_INN`, `CONTACT_EMAIL`, `HOSTING_NAME=Amvera Cloud`.
3. Проверьте адрес `https://<ваш адрес>/health`: ответ должен быть `{"ok":true}`.

Подойдёт и любой другой хостинг, который собирает `Dockerfile`, выдаёт HTTPS и даёт постоянный диск под `/data`. На Render для этого нужен платный тариф с диском: на бесплатном база стирается при каждом перезапуске.

## Сайт на GitHub Pages

1. На бесплатном аккаунте GitHub Pages работает только для **публичных** репозиториев. Секретов в коде нет, так что репозиторий можно сделать публичным. Второй вариант — тариф GitHub Pro.
2. Settings → Pages → Source: **GitHub Actions**.
3. Settings → Secrets and variables → Actions → **Variables**: `API_BASE_URL` (адрес сервера из прошлого шага), `BRAND`, `CONTACT_EMAIL`, `SELLER_NAME`, `SELLER_INN`, `HOSTING_NAME`, при желании `UPSTREAM_NAME`.
4. После push в `main` сайт соберётся сам (`.github/workflows/pages.yml`). Адрес — `https://<логин>.github.io/<репозиторий>/`. Если назвать репозиторий `<логин>.github.io`, сайт откроется по `https://<логин>.github.io/`.

Собрать сайт вручную: `npm run build:site` соберёт его в папку `site/` с настройками из `.env`.

## Коды для Plati и GGSel

Выпуск партии кодов:

```bash
curl -X POST https://<сервер>/admin/codes \
  -H "Authorization: Bearer $ADMIN_TOKEN" -H "Content-Type: application/json" \
  -d '{"rub": 100, "count": 50}' > codes-100.txt
```

Файл содержит по одному коду на строку. В Digiseller (Plati) создайте товар с выдачей уникальных кодов и загрузите файл. В базе коды хранятся только в виде хеша, поэтому храните файл, пока не загрузите его.

В описание товара добавьте такой текст: «Активируйте код на сайте `https://<сайт>` — получите ключ API. Адрес API: `https://<сервер>/v1`».

Другие админские команды:

| Запрос | Что делает |
|---|---|
| `GET /admin/stats` | ключи, партии кодов, выручка по моделям за 30 дней |
| `GET /admin/key?hint=sk-AbC` | найти ключ по началу |
| `POST /admin/recover {"code": "…"}` | новый ключ вместо утерянного, остаток переносится |
| `POST /admin/topup {"key_id": 5, "rub": 100}` | пополнить вручную |
| `POST /admin/disable {"key_id": 5}` | отключить ключ (`"disabled": false` — включить) |

Если есть доступ к консоли сервера, то же самое делает `node tools/admin.js`.

## Деньги

Наша цена — цена ProxyAPI × `MARKUP`. Сколько остаётся со 100 ₽ проданного кода, если покупатель израсходует весь баланс:

| MARKUP | ProxyAPI | Plati ≈10 % | НПД 4 % | Остаётся |
|---|---|---|---|---|
| 1,35 | 74 ₽ | 10 ₽ | 4 ₽ | ≈12 ₽ |
| 1,5 | 67 ₽ | 10 ₽ | 4 ₽ | ≈19 ₽ |
| 1,8 | 56 ₽ | 10 ₽ | 4 ₽ | ≈30 ₽ |

Комиссию Plati уточните в своём кабинете Digiseller: она зависит от способа оплаты.

## Как считаются деньги

- Перед запросом на балансе резервируется максимальная возможная стоимость. Выходные токены ограничиваются тем, что покрывает баланс, поэтому параллельные запросы не уводят его в минус.
- После ответа списывается стоимость по `usage` поставщика, остаток резерва возвращается.
- Если соединение оборвалось и `usage` не пришёл, списание идёт по оценке, а в истории такой запрос помечен звёздочкой.
- При ошибке поставщика деньги не списываются. Ошибки нашего аккаунта у ProxyAPI (ключ, баланс) клиент видит как 503, а текст ошибки уходит в лог сервера.
- Тексты запросов и ответов нигде не сохраняются.
